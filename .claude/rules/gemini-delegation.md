# Gemini 委任ルール

**Gemini CLI は、膨大なコンテキストとマルチモーダル機能を備えたリサーチのスペシャリストです。**

## コンテキスト管理 (重要)

**コンテキスト消費を意識してGeminiを使う。** Gemini出力は大きくなりがちなので、サブエージェント経由を推奨。

| 状況 | 推奨方法 |
|------|----------|
| 短い質問・短い回答 | 直接呼び出しOK |
| コードベース分析 | サブエージェント経由（出力大） |
| ライブラリ調査 | サブエージェント経由（出力大） |
| マルチモーダル処理 | サブエージェント経由 |

```
┌──────────────────────────────────────────────────────────┐
│  Main Claude Code                                        │
│  → 短い質問なら直接呼び出しOK                             │
│  → 大きな出力が予想されるならサブエージェント経由          │
│                                                          │
│  ┌────────────────────────────────────────────────────┐ │
│  │  Subagent (general-purpose)                         │ │
│  │  → Gemini CLIを呼び出す                              │ │
│  │  → 完全な出力を .claude/docs/research/ に保存します。   │ │
│  │  → 主要な調査結果のみを返します                         │ │
│  └────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

## Gemini について

Gemini CLI の優れた点:
- **100万トークンのコンテキストウィンドウ** — コードベース全体を一度に分析
- **Google 検索グラウンディング** — 最新情報にアクセス
- **マルチモーダル処理** — ビデオ、オーディオ、PDF の分析

Gemini は、情報を迅速に収集・統合できるリサーチアシスタントです。

**リサーチが必要になったら → サブエージェントに委任 → サブエージェントが Gemini に相談。**

## Gemini vs Codex: 適切なツールを選ぶ

| Task | Codex | Gemini |
|------|-------|--------|
| 設計上の決定 | ✓ | |
| デバッグ | ✓ | |
| コード実装 | ✓ | |
| トレードオフ分析 | ✓ | |
| 大規模コードベースの理解 | | ✓ |
| 実装前の調査 | | ✓ |
| 最新のドキュメント/ライブラリの調査 | | ✓ |
| ビデオ/オーディオ/PDF 分析 | | ✓ |

## Gemini に相談するタイミング

以下の場合は必ず Gemini に相談してください。

1. **実装前調査** - ベストプラクティス、ライブラリ比較
2. **大規模コードベース分析** - リポジトリ全体の理解
3. **ドキュメント検索** - 最新の公式ドキュメント、互換性のない変更点
4. **マルチモーダルタスク** - 動画、音声、PDFコンテンツの抽出

### トリガーフレーズ（ユーザー入力）

ユーザーが次のように言う場合は、Gemini に相談してください。

| Japanese | English |
|----------|---------|
| 「調べて」「リサーチして」「調査して」 | "Research" "Investigate" "Look up" |
| 「このPDF/動画/音声を見て」 | "Analyze this PDF/video/audio" |
| 「コードベース全体を理解して」 | "Understand the entire codebase" |
| 「最新のドキュメントを確認して」 | "Check the latest documentation" |
| 「〜について情報を集めて」 | "Gather information about X" |

## 相談すべきでないケース

Gemini をスキップするケース:

- 設計上の決定 (代わりに Codex を使用)
- コード実装 (代わりに Codex を使用)
- デバッグ (代わりに Codex を使用)
- 単純なファイル操作 (直接実行)
- テスト/lint の実行 (直接実行)

## 相談方法 (サブエージェント経由)

**重要: メインコンテキストを維持するにはサブエージェントを使用してください。**

### 推奨: サブエージェントパターン

`subagent_type: "general-purpose"` を指定してタスクツールを使用します。

```
タスクツールのパラメータ:
- subagent_type: "general-purpose"
- run_in_background: true (並列処理用)
- prompt: |
    Research: {topic}

    1. Gemini CLI を呼び出す:
       gemini -p "{research question}" 2>/dev/null

    2. 出力全体を .claude/docs/research/{topic}.md に保存する

    3. 簡潔な要約 (5～7 個の箇条書き):
       - 主な調査結果
       - 推奨アプローチ
       - 重要な注意事項
```

### タスクタイプ別のサブエージェントパターン

**調査パターン:**
```
プロンプト: |
  {topic} に関するベストプラクティスを調査します。

  gemini -p "調査: {topic}。推奨アプローチ、よくある落とし穴、ライブラリの推奨事項を含めます。" 2>/dev/null

  .claude/docs/research/{topic}.md に保存します。
  5～7 個の重要な箇条書きを返します。
```

**コードベース分析パターン:**
```
prompt: |
  {目的} のコードベースを分析します。

  gemini -p "アーキテクチャ、主要モジュール、データフロー、およびエントリポイントを分析します。" --include-directories . 2>/dev/null

  .claude/docs/research/codebase-analysis.md に保存します。
  アーキテクチャの概要と主要な分析情報を返します。
```

**マルチモーダルパターン:**
```
prompt: |
  {file} から情報を抽出します。

  gemini -p "{extraction prompt}" < {file_path} 2>/dev/null

  .claude/docs/research/{output}.md に保存します。
  抽出された主要な情報を返します。
```

### ステップ 2: 作業の続行

サブエージェントが処理中は、以下の操作を実行できます。
- 他のファイルで作業する
- テストを実行する
- Codex を参照するために別のサブエージェントを起動する

### ステップ 3: サマリーを受信する

サブエージェントは簡潔なサマリーを返します。完全な出力は、必要に応じて `.claude/docs/research/` で参照できます。

## Gemini CLI コマンドリファレンス

サブエージェント内での使用:

```bash
# Research
gemini -p "{question}" 2>/dev/null

# Codebase analysis
gemini -p "{question}" --include-directories . 2>/dev/null

# Multimodal
gemini -p "{prompt}" < /path/to/file.pdf 2>/dev/null

# JSON output
gemini -p "{question}" --output-format json 2>/dev/null
```

**言語プロトコル:**
1. Gemini に **英語** で質問する
2. サブエージェントが **英語** で応答を受信する
3. サブエージェントが出力を要約して保存する
4. メインエージェントが要約を受け取り、ユーザーに **日本語** で報告する

## なぜサブエージェントパターンなのか？

- **コンテキスト保持**: メインオーケストレーターは軽量なまま
- **フルキャプチャ**: サブエージェントはGeminiの出力全体をファイルに保存できます
- **簡潔なハンドオフ**: メインは重要な発見のみを受け取ります
- **並行作業**: バックグラウンドサブエージェントにより同時並行的な調査が可能になります

**調査にはGemini（サブエージェント経由）、推論にはCodex（サブエージェント経由）、オーケストレーションにはClaudeを使用します。**
