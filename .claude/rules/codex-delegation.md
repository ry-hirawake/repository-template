# Codex 委任ルール

**Codex CLI は非常に有能なサポーターです。**

## コンテキスト管理（重要）

**コンテキスト消費を意識してCodexを使う。** 大きな出力が予想される場合はサブエージェント経由を推奨。

| 状況 | 推奨方法 |
|------|----------|
| 短い質問・短い回答 | 直接呼び出しOK |
| 詳細な設計相談 | サブエージェント経由 |
| デバッグ分析 | サブエージェント経由 |
| 複数の質問がある | サブエージェント経由 |

```
┌──────────────────────────────────────────────────────────┐
│  Main Claude Code                                        │
│  → 短い質問なら直接呼び出しOK                             │
│  → 大きな出力が予想されるならサブエージェント経由          │
│                                                          │
│  ┌────────────────────────────────────────────────────┐ │
│  │  Subagent (general-purpose)                        │ │
│  │  → Codex CLI を呼び出す                              │ │
│  │  → 完全な応答を処理する                                │ │
│  │  → 重要な洞察を返す                                   │ │
│  └────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

## Codexについて

Codex CLIは、優れた推論能力とタスク完了能力を備えたAIです。
いつでも相談できる信頼できる上級専門家としてお考えください。

**難しい決断に直面したとき → サブエージェントに委任 → サブエージェントがコーデックスを参照します。**

## Codex を参照する場合

以下の場合は必ず Codex を参照してください。

1. **設計上の決定** - コードの構造化方法、使用するパターン
2. **デバッグ** - 原因が明らかでない場合、または最初の修正が失敗した場合
3. **実装計画** - 複数ステップのタスク、複数のアプローチ
4. **トレードオフ評価** - 選択肢の選択

### トリガーフレーズ（ユーザー入力）

ユーザーが次のように言う場合は Codex を参照してください:

| Japanese | English |
|----------|---------|
| 「どう設計すべき？」「どう実装する？」 | "How should I design/implement?" |
| 「なぜ動かない？」「原因は？」「エラーが出る」 | "Why doesn't this work?" "Error" |
| 「どちらがいい？」「比較して」「トレードオフは？」 | "Which is better?" "Compare" |
| 「〜を作りたい」「〜を実装して」 | "Build X" "Implement X" |
| 「考えて」「分析して」「深く考えて」 | "Think" "Analyze" "Think deeper" |

## 参照すべきでないケース

単純で分かりやすいタスクの場合は、Codex は使用しないでください。

- 単純なファイル編集（タイプミスの修正、小さな変更）
- 明示的なユーザー指示に従う
- 標準的な操作（git コミット、テストの実行）
- 明確で単一の解決策があるタスク
- ファイルの読み取り/検索

## クイックチェック

「重要な決断をしようとしているのか？」と自問自答してみましょう。

- はい → まず Codex を参照する
- いいえ → 実行に進む

## サブエージェント経由のコンサルト方法

**重要: メインコンテキストを維持するにはサブエージェントを使用してください。**

### 推奨: サブエージェントパターン

`subagent_type: "general-purpose"` でタスク ツールを使用します。

```
タスクツールパラメータ:
- subagent_type: "general-purpose"
- run_in_background: true (並列処理用)
- prompt: |
    {タスクの説明}

    Codex CLI を呼び出す:
    codex exec --model gpt-5.3-codex --sandbox read-only --full-auto "
    {Codex への質問}
    " 2>/dev/null

    簡潔な要約を返す:
    - 主な推奨事項
    - 主な根拠 (2～3 点)
    - 懸念事項またはリスク
```

### 直接呼び出し（必要な場合のみ）

直接 Bash 呼び出しは、次の場合にのみ使用してください。
- 簡単で簡単な質問（1段落未満の回答が想定される）
- サブエージェントのオーバーヘッドが正当化されない

```bash
# 単純なクエリのみ
codex exec --model gpt-5.3-codex --sandbox read-only --full-auto "Brief question" 2>/dev/null
```

### Sandbox Modes

| Mode | Sandbox | Use Case |
|------|---------|----------|
| 分析 | `read-only` | 設計レビュー、デバッグ分析、トレードオフ |
| 作業 | `workspace-write` | 実装、修正、リファクタリング (サブエージェント推奨) |

**言語プロトコル:**
1. Codexに**英語**で質問する
2. サブエージェントが**英語**で回答を受け取る
3. サブエージェントが要約し、メインエージェントに戻る
4. メインエージェントがユーザーに**日本語**で報告する

## なぜサブエージェントパターンなのか？

- **コンテキストの保持**: メインオーケストレーターは軽量なまま
- **完全な分析**: サブエージェントはCodexレスポンス全体を処理可能
- **簡潔なハンドオフ**: メインは実行可能なサマリーのみを受け取る
- **並行作業**: バックグラウンドサブエージェントが同時実行タスクを可能にする

**委任をためらわないでください。サブエージェント + Codex = 効率的なコラボレーション。**
