# Codex設計相談ガイド

## 目的

プロジェクト要件に最適な技術スタック構成をCodexの深い推論能力で検証・最適化する。

## 設計相談プロンプトテンプレート

```
以下のプロジェクトに最適な技術スタック構成を検証し、改善提案をしてください。

【プロダクト仕様】
{product.mdの要約}

【選定済み技術スタック】
{tech_stack.mdの内容}

【Gemini調査結果】
{tech-research-guideの調査結果サマリー}

【相談事項】
1. **技術スタック構成の妥当性**
   - 各技術の組み合わせに問題はないか
   - バージョン互換性・統合の難易度
   - 過剰/過小な技術選定はないか
   - プロダクト要件との整合性

2. **アーキテクチャパターンの推奨**
   - このプロジェクトに最適なアーキテクチャ
   - モノリス vs マイクロサービス vs モジュラーモノリス
   - レイヤーアーキテクチャ・ディレクトリ構造
   - 理由と将来の拡張性

3. **代替案との比較**
   - tech_stack.mdで不採用とした技術の再評価
   - 新たに検討すべき技術（Gemini調査結果から）
   - コスト・学習コスト・保守性の総合比較

4. **リスク軽減策**
   - 技術的負債の予防策
   - ベンダーロックイン回避
   - 将来の技術移行戦略
   - パフォーマンス・セキュリティリスク対策

5. **開発効率化**
   - CI/CD推奨構成
   - テスト戦略（単体/統合/E2E）
   - コード品質担保（Linter/Formatter/型チェック）
   - 監視・ロギング戦略

6. **認知的負債の最小化**
   - チーム学習コストの評価
   - ドキュメント整備の推奨
   - オンボーディング戦略

7. **2026年先進技術の統合**
   - AI/LLM統合の設計
   - Context Engineering導入
   - Harness Engineering的アプローチ

【出力形式】
以下の構造化フォーマットで出力してください：

## 総合評価
- 技術選定: [1-5点] + 理由
- アーキテクチャ: [1-5点] + 理由
- 実現可能性: [1-5点] + 理由

## 承認（このまま進める）
- [技術1]: 理由
- [技術2]: 理由

## 要改善（変更を推奨）
- [技術X]: 現状の問題 → 代替案 + 理由

## 追加推奨
- [技術Y]: 必要性と導入メリット

## アーキテクチャ提案
- パターン: [推奨パターン名]
- 理由: [詳細な根拠]
- ディレクトリ構造案: [具体例]

## リスクと対策
- [リスク1]: 対策
- [リスク2]: 対策
```

## 出力の活用

- 検証結果を `.dgic/logs/tech-design-init_consultation_YYYYMMDD.md` に保存
- 要改善項目があればユーザーに説明し、tech_stack.md修正を提案
- アーキテクチャ提案は後続のcmd-prj-initで活用
- 承認された技術はそのまま採用、修正箇所のみ再検討
