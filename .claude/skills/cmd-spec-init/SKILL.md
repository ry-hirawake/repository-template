プロジェクトの開始時に１度だけ使用されるSkill。ユーザーにヒアリングをしながら作成するシステムの概要、目的、制約条件をまとめる。プロジェクトの最終的な完成系をを把握し、以降のタスク遂行の指針とするための重要なステップ。
それ以外の作業では実行しない。

## Goal
作成するシステムの概要、目的、ターゲット、利用シーン、最終的な完成形を把握し、`.dgic/steering/product.md`にまとめる。

## Input (必要ならユーザーに質問してよい)
- システムの概要を教えてください。
- システムの目的は何ですか？
- ターゲットユーザーは誰ですか？
- システムはどのような利用シーンを想定していますか？
- 最終的な完成形はどのようなものを想定していますか？
- システムに対する制約条件や要件はありますか？
- 競合するシステムや類似のシステムはありますか？それらと比べて、どのような差別化ポイントがありますか？
- システムの成功をどのように測定しますか？（例：ユーザー数、利用頻度、満足度など）
- システムの開発にあたって、特に重視している点はありますか？（例：パフォーマンス、セキュリティ、ユーザーエクスペリエンスなど）
- システムの開発にあたって、特に懸念している点はありますか？（例：技術的な難易度、リソースの制約、競合の存在など） 
- システムの開発にあたって、特に注目している技術やアプローチはありますか？（例：特定のプログラミング言語、フレームワーク、アーキテクチャなど）
- システムの開発にあたって、特に避けたいことやリスクはありますか？（例：過度な複雑さ、技術的な負債、ユーザーの混乱など）
- システムの開発にあたって、特に重視しているユーザーのニーズや要望はありますか？（例：特定の機能、使いやすさ、カスタマイズ性など）
- システムの開発にあたって、特に重視している将来の展望やビジョンはありますか？（例：将来的な機能追加、拡張性、他のシステムとの連携など）

### カスタムヒアリング項目
必要に応じて、ユーザーが追加・削除したいヒアリング項目を指定できる。  
（例：「このプロジェクト特有の質問を追加したい場合は教えてください」など）

## 実行履歴・再実行ガード
- このSkillはプロジェクト開始時に一度だけ実行してください。
- `.dgic/steering/product.md` が既に存在する場合は、上書き前にユーザーへ確認し、実行履歴を `.dgic/steering/product_init.log` に記録してください。
- 再実行時は「既に初期化済みです。再実行しますか？」とユーザーに確認し、許可があれば上書きしてください。

### 実行履歴ログのフォーマット例

```text
[YYYY-MM-DD HH:MM:SS] user: <ユーザー名> action: <init|overwrite|cancel> file: product.md note: <任意のメモ>
```

#### 記録例

```text
[2026-02-25 10:15:32] user: hirawake action: init file: product.md note: 初回作成
[2026-02-25 10:20:10] user: hirawake action: overwrite file: product.md note: ユーザー確認の上で再実行
[2026-02-25 10:21:00] user: hirawake action: cancel file: product.md note: ユーザーが再実行をキャンセル
```

## Review Checklist (この観点で評価する)
- 正しさ：境界条件、例外処理、null安全、オフバイワン
- 影響範囲：破壊的変更、既存API/仕様への副作用
- 可読性：命名、責務分離、重複、複雑度（Cognitive Complexity）
- テスト：不足しているケース、回帰リスク
- セキュリティ：入力検証、秘密情報漏洩、過剰なログ
