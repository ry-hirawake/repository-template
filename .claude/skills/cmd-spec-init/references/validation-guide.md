# Codex妥当性検証ガイド

## 目的

作成したproduct.mdの実現可能性・論理的整合性をCodexの深い推論能力で検証する。

## 検証プロンプトテンプレート

```
以下のプロダクト仕様書を、技術的実現可能性と論理的整合性の観点から検証してください。

【product.md全文】
{product.mdの内容}

【検証観点】
1. **実現可能性の評価**
   - 技術的難易度（Low/Medium/High/Critical）
   - 制約条件（予算・期間・人員）との整合性
   - MVP vs 完成形のバランス
   - リスクの見落とし

2. **論理的整合性**
   - 目的 vs 成功指標のアライメント
   - ターゲット vs 提供価値の妥当性
   - 制約 vs 品質要件の矛盾
   - 差別化ポイント vs 競合分析の説得力

3. **スコープの適切性**
   - MVPスコープが大きすぎる/小さすぎる
   - 優先度付けの妥当性
   - 段階的リリース計画の現実性

4. **リスク分析の網羅性**
   - 見落としている重大リスク
   - 対策の実効性
   - 確率・影響度の評価の妥当性

5. **認知的負債チェック**
   - 曖昧な表現・未定義の用語
   - 測定不可能な成功指標
   - 検証不可能な仮説

【出力形式】
以下の構造化フォーマットで出力してください：

## 総合評価
- 実現可能性: [1-5点] + 理由
- 整合性: [1-5点] + 理由
- スコープ: [1-5点] + 理由

## 重大な問題（即座に修正すべき）
- [問題1]: 具体的な指摘と修正提案
- [問題2]: 具体的な指摘と修正提案

## 改善推奨（検討すべき）
- [推奨1]: 理由と代替案
- [推奨2]: 理由と代替案

## 追加すべき検討事項
- [事項1]: なぜ必要か
- [事項2]: なぜ必要か

## 強み（このまま維持）
- [強み1]: 評価理由
- [強み2]: 評価理由
```

## 出力の活用

- 検証結果を `.dgic/logs/spec-init_validation_YYYYMMDD.md` に保存
- 重大な問題があればユーザーに即座に通知
- 改善推奨をproduct.mdに反映するか確認
- 検証ログは将来の意思決定の根拠として保存
