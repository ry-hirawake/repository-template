# Codex 設計ガイド

## 設計相談プロンプトテンプレート

```
以下のプロジェクトの初期アーキテクチャを設計してください:

【技術スタック】
{tech_stack}

【プロジェクト要件】
{product_requirements}

【Gemini調査結果】
{research_results}

【設計項目】
1. アーキテクチャパターン選定（理由含む）
2. ディレクトリ構造の設計原則
3. モジュール分割戦略
4. データフロー設計
5. エラーハンドリング戦略
6. テスト戦略
7. スケーラビリティ考慮事項
8. セキュリティ設計

【制約条件】
- {product_constraints}

【出力】
1. 推奨アーキテクチャ（図・説明）
2. 初期ディレクトリ構造
3. 主要設定ファイルの内容
4. README骨子
5. 設計判断の根拠
```

## 設計結果の活用

Codexの設計を元に:
- ディレクトリ作成
- 初期ファイル生成
- 設定ファイル配置
- ドキュメント生成

## 設計原則

Codexに常に確認させる原則:
- Clean Architecture
- SOLID原則
- 保守性優先
- テスタビリティ
- 認知的負債の最小化
