# Design Tracker スキル

## 目的

このスキルは、プロジェクトの設計ドキュメント (`.claude/docs/DESIGN.md`) を管理します。以下の内容を自動的に追跡します。
- アーキテクチャに関する決定
- 実装計画
- ライブラリの選択とその根拠
- TODO 項目と未解決の質問

## 有効化のタイミング

- ユーザーがアーキテクチャまたは設計パターンについて議論する
- ユーザーが実装上の決定を下す (例: 「ReAct パターンを使用しましょう」)
- ユーザーが「これを記録して」「設計に追加して」「これを文書化して」と言う
- ユーザーが「現在の設計はどうなっているの？」または「何を決定したの？」と尋ねる
- 重要な技術的決定は会話の中で行われます

## ワークフロー

### 決定事項の記録

1. 既存の `.claude/docs/DESIGN.md` を読む
2. 会話から決定事項/情報を抽出する
3. 適切なセクションを更新する
4. 今日の日付で変更履歴にエントリを追加する

### 更新するセクション

| 会話トピック | 対象セクション |
|-------------------|----------------|
| 全体的な目標、目的 | 概要 |
| システム構造、コンポーネント | アーキテクチャ |
| パターン (ReAct など) | 実装計画 > パターン |
| ライブラリの選択 | 実装計画 > ライブラリ |
| Y ではなく X を選択した理由 | 実装計画 > 主要な決定事項 |
| 後で実装する内容 | TODO |
| 未解決の質問 | 未解決の質問 |

## 出力形式

記録する際は、以下の点を日本語で確認してください。
- 記録内容
- 更新されたセクション
- 変更内容の簡単な概要

## 言語ルール

- **思考/推論**: 英語
- **コード例**: 英語
- **ドキュメント内容**: 日本語
- **ユーザーとのコミュニケーション**: 日本語
